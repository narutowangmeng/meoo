# 专业规则引擎设计方案

## 一、业界规则引擎调研总结

### 主流开源规则引擎

| 引擎 | 特点 | 适用场景 |
|------|------|---------|
| **Drools** | Java生态、RETE算法、功能最全 | 金融风控、复杂业务规则 |
| **Node-RED** | 可视化流程、拖拽节点、IBM开源 | IoT、流程编排、快速原型 |
| **Easy Rules** | 轻量级、注解驱动、易集成 | 简单规则、嵌入式场景 |
| **URule** | 国产开源、可视化规则设计 | 企业级业务规则管理 |
| **LiteFlow** | 规则编排、组件化、热刷新 | 业务流程编排 |

### 规则引擎核心要素

1. **规则定义**：条件（Condition）+ 动作（Action）
2. **事实对象（Fact）**：规则操作的数据对象
3. **工作内存（Working Memory）**：存储事实对象的上下文
4. **推理引擎**：匹配规则、执行动作

## 二、推荐方案：可视化规则设计器

参考Node-RED和URule的设计，采用**可视化条件构建器** + **规则流编排**的方式。

### 2.1 规则结构升级

```typescript
// 规则定义
interface RuleDefinition {
  id: string;
  name: string;
  category: string;
  level: WarningLevel;
  
  // 触发条件（可视化构建）
  trigger: {
    type: 'simple' | 'complex' | 'composite';
    conditions: Condition[];
    logic: 'AND' | 'OR' | 'CUSTOM';
    customLogic?: string; // 如: (A AND B) OR (C AND D)
  };
  
  // 事实对象定义
  facts: FactDefinition[];
  
  // 动作定义
  actions: Action[];
  
  // 规则流（可选，用于复杂场景）
  flow?: RuleNode[];
  
  // 元数据
  frequency: string;
  policyBasis: string;
  enabled: boolean;
}

// 条件定义
interface Condition {
  id: string;
  factId: string;           // 关联的事实对象
  field: string;            // 字段路径，如: "debtRatio"
  operator: Operator;       // 操作符
  value: any;               // 比较值
  valueType: 'constant' | 'variable' | 'expression';
  
  // 高级选项
  aggregation?: Aggregation; // 聚合函数
  timeWindow?: TimeWindow;   // 时间窗口
}

// 操作符枚举
type Operator = 
  | 'EQ' | 'NE'           // 等于、不等于
  | 'GT' | 'GE' | 'LT' | 'LE'  // 大于、大于等于、小于、小于等于
  | 'BETWEEN' | 'NOT_BETWEEN'  // 在范围内
  | 'IN' | 'NOT_IN'       // 在列表中
  | 'CONTAINS' | 'NOT_CONTAINS' // 包含
  | 'STARTS_WITH' | 'ENDS_WITH' // 开头/结尾
  | 'MATCHES'             // 正则匹配
  | 'IS_EMPTY' | 'IS_NOT_EMPTY' // 空值判断
  | 'EXISTS' | 'NOT_EXISTS'; // 存在性判断

// 事实对象定义
interface FactDefinition {
  id: string;
  name: string;
  type: 'entity' | 'event' | 'metric' | 'api';
  source: string;           // 数据来源
  fields: FactField[];
}

interface FactField {
  name: string;
  type: 'string' | 'number' | 'boolean' | 'date' | 'array' | 'object';
  path: string;             // JSON路径
  description?: string;
  unit?: string;            // 单位
}

// 动作定义
interface Action {
  id: string;
  type: 'warning' | 'notification' | 'webhook' | 'script' | 'workflow';
  config: Record<string, any>;
}
```

### 3.3 规则执行引擎（伪代码）

```typescript
class RuleEngine {
  // 执行单条规则
  async executeRule(rule: RuleDefinition, context: ExecutionContext): Promise<RuleResult> {
    // 1. 加载事实对象
    const facts = await this.loadFacts(rule.facts, context);
    
    // 2. 评估条件
    const conditionResult = await this.evaluateConditions(
      rule.trigger.conditions, 
      rule.trigger.logic,
      facts
    );
    
    // 3. 如果条件满足，执行动作
    if (conditionResult.matched) {
      const actionResults = await this.executeActions(rule.actions, facts, context);
      return {
        ruleId: rule.id,
        triggered: true,
        conditionResult,
        actionResults,
        timestamp: new Date()
      };
    }
    
    return {
      ruleId: rule.id,
      triggered: false,
      conditionResult,
      timestamp: new Date()
    };
  }
  
  // 评估条件
  private async evaluateConditions(
    conditions: Condition[], 
    logic: string,
    facts: Record<string, any>
  ): Promise<ConditionResult> {
    const results = await Promise.all(
      conditions.map(c => this.evaluateSingleCondition(c, facts))
    );
    
    // 根据逻辑组合条件结果
    let matched: boolean;
    switch (logic) {
      case 'AND':
        matched = results.every(r => r.matched);
        break;
      case 'OR':
        matched = results.some(r => r.matched);
        break;
      default:
        // 自定义逻辑解析
        matched = this.evaluateCustomLogic(logic, results);
    }
    
    return { matched, details: results };
  }
  
  // 评估单个条件
  private async evaluateSingleCondition(
    condition: Condition, 
    facts: Record<string, any>
  ): Promise<SingleConditionResult> {
    const fact = facts[condition.factId];
    const fieldValue = this.getFieldValue(fact, condition.field);
    
    // 如果有聚合函数，先计算
    let compareValue = fieldValue;
    if (condition.aggregation) {
      compareValue = this.applyAggregation(fieldValue, condition.aggregation);
    }
    
    // 执行比较
    const matched = this.compare(compareValue, condition.operator, condition.value);
    
    return {
      conditionId: condition.id,
      matched,
      actualValue: compareValue,
      expectedValue: condition.value,
      operator: condition.operator
    };
  }
  
  // 比较操作
  private compare(actual: any, operator: Operator, expected: any): boolean {
    switch (operator) {
      case 'EQ': return actual === expected;
      case 'NE': return actual !== expected;
      case 'GT': return actual > expected;
      case 'GE': return actual >= expected;
      case 'LT': return actual < expected;
      case 'LE': return actual <= expected;
      case 'BETWEEN': return actual >= expected[0] && actual <= expected[1];
      case 'IN': return expected.includes(actual);
      case 'CONTAINS': return actual?.includes(expected);
      // ... 其他操作符
      default: return false;
    }
  }
}
```

## 四、前端组件设计

### 4.1 条件构建器组件

```typescript
// ConditionBuilder.tsx
interface ConditionBuilderProps {
  value: TriggerConfig;
  onChange: (value: TriggerConfig) => void;
  availableFacts: FactDefinition[];
}

// 使用方式
<ConditionBuilder
  value={rule.trigger}
  onChange={(trigger) => setRule({ ...rule, trigger })}
  availableFacts={predefinedFacts}
/>
```

### 4.2 组件功能

1. **可视化条件树**：支持嵌套的条件组（AND/OR）
2. **字段选择器**：从事实对象中选择字段
3. **操作符选择**：根据字段类型动态显示可用的操作符
4. **值编辑器**：支持常量、变量、表达式三种类型
5. **高级选项**：时间窗口、聚合函数、空值处理

## 五、推荐实现路径

### 阶段1：基础条件构建器（1-2天）
- 实现简单的条件列表（支持AND/OR）
- 字段选择器（从预定义事实对象中选择）
- 基本的操作符（> < = 等）

### 阶段2：高级功能（2-3天）
- 嵌套条件组
- 时间窗口和聚合函数
- 条件模板（快速选择常用条件）

### 阶段3：规则流（可选）
- 可视化规则流设计器
- 节点拖拽和连线
- 规则调试和测试
